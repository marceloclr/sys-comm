# Prompt de continuidade — sys-comm → APK Android (caminho B)

## 1. Objetivo
O usuário pediu: "Como especialista em desenvolvimento de aplicações para android avalie profundamente o sistema sys-comm e estime a migração dele para um apk contendo todos os recursos da aplicação web." Depois da avaliação, decidiu: "pode começar pelo caminho B".

Caminho B = APK com WebView que carrega o próprio `index.html` do sys-comm **de dentro do APK** (offline), com pontes nativas para o que o WebView não faz sozinho. Estimativa entregue: 14 a 18 dias úteis no total. A primeira etapa combinada é a base do projeto mais as pontes de download e de compartilhamento.

## 2. Decisões e preferências
- Escolhido o caminho B. O caminho A (TWA, como o app do TCS) e o C (reescrita nativa em Kotlin) foram descartados.
- Respostas sempre em pt-BR. Commit no padrão Conventional Commits e push para o servidor ativo (GitLab) ao terminar cada edição.
- O xadrez da tela inicial é uma **fachada**: o app se chama "Xadrez" e tem ícone de xadrez. Nada no app (nome, ícone, pacote, diálogos) pode mencionar "comunicação", "sistema" ou "login". Pacote planejado: `io.gitlab.marceloclr.xadrez`.
- O `index.html` web continua sendo a **fonte única**. O APK é gerado a partir dele por um script de preparo, sem editar o código web (o usuário exige preservar o sistema como está).
- Ainda por decidir pelo usuário (não decida sozinho): (1) como gerir os usuários no APK, já que o `exportarSistemaAtualizado` regrava o HTML. A sugestão foi um arquivo de usuários cifrado para exportar e importar; a alternativa é gerar um APK novo a cada mudança; (2) o token do Telegram: revogar no BotFather e decidir se vai embutido ou por configuração; (3) a distribuição: sugerida a instalação direta, como no TCS, porque a Play Store tende a recusar.

## 4. Pendências (em ordem)
1. Criar `sys-comm/android/` em Android puro, Java, **sem dependências** (dá para fazer o build offline): copiar `gradlew` e `gradle/wrapper/*` de `~/Documentos/GitHub/tcs/android/`; `settings.gradle`; `build.gradle` com AGP 8.9.1 e repositórios google() e mavenCentral(); `gradle.properties`; `app/build.gradle` com namespace e applicationId `io.gitlab.marceloclr.xadrez`, minSdk 24, compile e target 36, e signingConfig lendo `~/.android-keys/xadrez.jks` e `.senha`.
2. Alterar o `.gitlab-ci.yml` para o Pages pular a pasta `android` (por exemplo `node_modules|_*|android) continue`). Senão o código do APK vai para o site.
3. `android/preparar-web.py`: gera `app/src/main/assets/www/` a partir de `../index.html`. Troca `https://cdn.jsdelivr.net/npm/three@0.170.0/` por `./vendor/three@0.170.0/` (importmap, integrity e modulepreload); baixa os 17 arquivos para um cache ignorado pelo git e confere o SHA-384 de cada um contra o SRI do próprio index; copia o `tg-config.js`; injeta `<script src="android-ponte.js">` antes do `</head>`. Os assets gerados vão para o `.gitignore`.
4. `android-ponte.js`: intercepta `HTMLAnchorElement.prototype.click` (e cliques diretos em links com `download`) quando o href é blob: ou data:. Faz `fetch` → base64 → `AndroidPonte.salvar(nome, mime, b64)`. Também consulta `AndroidPonte.arquivoRecebido()` e, quando `#main-system` estiver visível, abre a imagem em Revelar.
5. `MainActivity.java`: WebView servindo os assets por `shouldInterceptRequest` em `https://appassets.androidplatform.net/assets/...`, com MIME correto (`text/javascript` para os módulos). **Não usar file://**, porque o `crypto.subtle` exige contexto seguro. Também: FLAG_SECURE; insets das barras do sistema (o Android 15 força edge-to-edge); `onShowFileChooser`; GPS com permissão em tempo de execução (`onGeolocationPermissionsShowPrompt`); `onJsAlert` e `onJsConfirm` com AlertDialog sem título (o padrão mostra o domínio); links externos no navegador; depuração do WebView só em build debug; Voltar → `moveTaskToBack`.
6. `Ponte.java`: `salvar` grava o arquivo no cache e abre um diálogo "Salvar no aparelho" (ACTION_CREATE_DOCUMENT) ou "Compartilhar" (ACTION_SEND por um ContentProvider próprio, porque não há androidx). Para PNG, avisar que deve ir como documento, não como foto. `arquivoRecebido` devolve um JSON `{nome, mime, b64}` do intent recebido.
7. Manifest: INTERNET, ACCESS_FINE_LOCATION e ACCESS_COARSE_LOCATION; `allowBackup=false`; activity `singleTask` com MAIN/LAUNCHER, SEND `image/*` e VIEW `image/png`; provider. Recursos: nome "Xadrez", ícone vetorial de peça de xadrez (adaptativo em v26 e vetor simples para 24–25), tema escuro sem action bar.
8. `android/construir.sh` (prepara, depois `./gradlew assembleRelease --offline` com `JAVA_HOME=~/Android/jdk17` e `ANDROID_HOME=~/Android/Sdk`) e `android/LEIA-ME.md`.
9. Testar: o build tem que sair; os assets em `www/` devem rodar no Chromium headless (há navegadores em `~/.cache/ms-playwright`; o módulo Python do playwright não está instalado, verificar o Node) com um `AndroidPonte` falso, conferindo que o three.js carrega do vendor com SRI e que os downloads passam pela ponte. O teste no aparelho fica com o usuário (`adb install`).
10. Commit e push. Depois, as etapas seguintes da estimativa: segurança (logout em segundo plano, armazenamento cifrado pelo Keystore no lugar do XOR, bloqueio de tentativas persistente), gestão de usuários (depende da decisão 1), ajustes de celular e testes em 3 aparelhos.

## 5. Armadilhas
- O repositório sys-comm é **público** e o Pages publica tudo da raiz. Nunca versionar a chave, a senha da chave, o `acessos-sys-comm.txt` ou o APK com segredos.
- O `tg-config.js` com o token já está público. Dentro do APK ele também pode ser extraído.
- `file:///android_asset` não é contexto seguro e o `crypto.subtle` some. Use o host https interceptado.
- A exportação revoga a URL do blob em 600 ms, então a ponte precisa fazer o `fetch` do blob logo no clique.
- O importmap tem `integrity`, que exige o arquivo idêntico, byte a byte, ao do jsDelivr.
- O PNG esteganográfico se perde se for enviado como foto no WhatsApp ou no Telegram.
- O `sessionStorage` (bloqueio de tentativas) zera ao fechar o app.
- Não misturar com o kriptos (aposentado). Ler a memória `sys_comm_xadrez_disfarce.md` antes de mexer no xadrez.
- Use `git fetch` antes de trabalhar, porque a outra máquina também publica.
